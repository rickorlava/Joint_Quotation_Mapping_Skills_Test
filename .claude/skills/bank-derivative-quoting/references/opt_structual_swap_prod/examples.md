# 结构性掉期产品样例

## 0. 文档定位
本文件定义结构性掉期报价 agent 的 **调用样例**
## 1. 典型调用示例

> **说明**:以下样例覆盖常见场景与边缘场景。学习重点不是样例本身,而是每条样例后的**处理理由**——它体现了从自然语言到内部约束的推理路径。

### 1.1 基础干净表达

基础干净表达是标准表达，分为给 term 求 K 和给 K 求 term，以及兼容标准历史格式的表达

#### 示例A1:给 term 求 K

用户:
> 3M 结汇结构性掉期

处理:只给了 term 和方向,走报价范式 **1.1 基准单点报价给 term 求 K** 并输出。

#### 示例A2:给 K（无 term）
用户:
> 结构性掉期,结汇,K 定在 7.05

处理:只给了 K 和方向。结构性掉期需要 term 锚定掉期结构，K 不再唯一决定 term。须追问 term 后走 **1.3 K 确定求 prem**。

追问输出:
```
<<<TYPE_START>>> chat <<<TYPE_END>>>
<<<CONTENT_START>>>
K=7.05 已收到。请问您希望以哪个期限来搭配这个 K？
(如: 1M、3M、6M、1Y 等)
<<<CONTENT_END>>>
```

#### 示例A3：历史格式
用户:
> 结构性掉期 USDCNY 3M 100pips 结汇 产品报价

处理:按位置解析:币种=USDCNY、期限=3M、中收=100、方向=settle。归一化后走报价范式 **1.1 基准单点报价给 term 求 K** 并输出。

#### 示例 A4:只给交割日
用户:
> 2026-09-01 交割的结汇结构性掉期

处理:有 `delivery_date`=2026-09-01,视为**1.2 基准单点报价给 delivery 求 K**。

#### 示例 A5：币种对比
用户:
> 给我6m交割的结汇结构性掉期，美元和欧元都看下

处理:用户要求美元和欧元都看，默认本币计价下，客户想看的两个货币对USDCNY和EURCNY → 走 **1.12 币种对比**。客户明确指定了 term=6m，被组合范式为 **1.1 基准单点报价给 term 求 K**

调用计划:
```
调用 1:--term 6M --currency-pair=USDCNY
调用 2:--term 6M --currency-pair=EURCNY
汇总:2行一表,列头含 currency 与对应 K
```


### 1.2 市场观点表达

#### 示例B1:否定式观点+给出 term 的混合表达
用户:
> 3M 结汇结构性掉期,我觉得人民币不会贬值到 7.20

处理:
- "3M 结汇结构性掉期" → 结汇情境下 term = 3M，明确指出了结构性掉期的输入参数
- "我觉得人民币不会贬值到 7.20" → 客户给出了否定式市场观点，推测隐含 strike = 7.2
- 按照混合表达中的**直接参数 > 否定式观点**优先级，选定输入参数为 3M，走报价范式 **1.1 基准单点报价给 term 求 K** 并输出

#### 示例B2:否定式观点
用户:
> 结汇结构性掉期,我觉得人民币不会贬值到 7.20

处理:
- "结汇结构性掉期" → 结汇情境
- "我觉得人民币不会贬值到 7.20" → 客户给出了否定式市场观点，推测隐含 strike = 7.2
- 客户没有指定 term，且市场观点隐含了一个 K，走报价范式 \*\*1\.3 K 确定求 prem\*\* 并输出

#### 示例B3: 区间肯定式观点
用户:
> 结构性掉期结汇,我觉得未来三个月汇率大概率在 7.00 到 7.10 之间

处理:
- "大概率在 7.00-7.10 之间" 是区间观点
- 结汇方向 → K 设在区间上沿之上,取 7.10 作为初始候选
- 期限"未来三个月"是在市场观点中表达的 → term=3M
- 用户仅在**市场观点**中有参数，在结构性掉期里没有对应参数的修饰词，因此 K 和 term 都是市场观点隐含的，不属于混合表达
- 由于 K 与 term 同时都是市场观点隐含，不属于混合表达的处理方式 → 走过约束拦截,以友好方式说明推理并让用户选择

输出:
```
<<<TYPE_START>>> chat <<<TYPE_END>>>
<<<CONTENT_START>>>
从您的表达,我理解为:您认为汇率大概率在 7.00-7.10 区间内,愿意在汇率超出上限时承担行权 —— 对应 K=7.10 是个合适的起点。
期限这一面您提及三个月。由于结构性掉期不能同时指定 K 与期限,请问您希望:
- 以 K=7.10 求对应期限
- 以 3M 求对应 K
<<<CONTENT_END>>>
```

- 若用户后续选"以 K=7.10 求期限"，则走报价范式 \*\*1\.3 K 确定求 prem\*\* 并输出

#### 示例B4: 区间肯定式观点+混合表达，term 作为明确的变量
用户:
> 给我3个月结汇的结构性掉期报价,我觉得未来三个月汇率大概率在 7.00 到 7.10 之间

处理:
- "大概率在 7.00-7.10 之间" 是区间观点
- 结汇方向 → K 设在区间上沿之上,取 7.10 作为初始候选
- 期限"未来三个月"是在市场观点中表达的 → term=3M
- "3个月结汇的结构性掉期"，明确指定了 term 为 3m
- 总结：客户在市场观点中隐含了 3m 的 term 和 7.10 的K，但给出了明确的 "3个月" 结构性掉期输入参数，属于**混合表达**，只是市场观点和明确参数的 term 是一样的。按照混合表达中的**直接参数 > 否定式观点**优先级，我们忽略客户市场观点中隐含的 K，走报价范式 **1.1 基准单点报价给 term 求 K** 并输出

### 1.4 补贴点数反查

此为核心场景

#### 示例D1:用户给出补贴目标

用户:
> 结构性掉期,结汇,希望近端补贴 100 点左右

处理:
- 识别 `target_prem_pips = 100`，走报价范式 **1.10 按近端补贴点数反查**
- 在 1M~12M 范围内扫描 6 个代表性 term(1M、2M、3M、6M、9M、12M)
- 筛选出补贴最接近 100 的两个 term 点位
- 只输出这两个方案

调用计划:
```
调用 1:--term 1M   → 取补贴值
调用 2:--term 2M   → 取补贴值
调用 3:--term 3M   → 取补贴值
调用 4:--term 6M   → 取补贴值
调用 5:--term 9M   → 取补贴值
调用 6:--term 12M  → 取补贴值
汇总:筛选出补贴最接近 100 的 2 个 term,返回这 2 个的完整方案
```

输出结构(示意):
```
期限 | K | 近端补贴点数
{term_a} | {K_a} | {prem_a}  (最接近目标上方)
{term_b} | {K_b} | {prem_b}  (最接近目标下方)
```

#### 示例D2:用户给出补贴目标，但目标超出了曲线范围

用户:
> 结构性掉期,结汇,希望近端补贴 500 点

处理:
- 识别 `target_prem_pips = 500`，走报价范式 **1.10 按近端补贴点数反查**
- 扫描后发现最大补贴仅有 180 点(示意)
- 仍返回最接近的那个 term 方案
- 在输出中说明"目标补贴 500 点在当前市场曲线上不可达,以下是最接近的方案"

#### 示例D3：用户限定了期限范围 + 补贴目标
用户:
> 半年以内的结构性掉期,希望补贴 80 点

处理:
- 识别 `target_prem_pips = 80` 且期限限定"半年以内"，走报价范式 **1.10 按近端补贴点数反查**
- 在 1M~6M 区间内扫描(而不是 1M~12M)
- 期限集合收窄为 1M、2M、3M、4M、5M、6M(≤6 次预算)
- 筛选补贴最接近 80 的两个

### 1.14 给 term+补贴点数双约束求K

#### 示例 A6:给 term，指定了近端补贴点数

**三种等价输入形态：**
1. 结果导向：`"近端结汇价格是6.XXXX"`
2. 直接补贴：`"近端补贴500pips"`
3. 对比表达：`"近端比普通即期结汇价格高500pips"`

用户：
> 3个月的结构性掉期结汇，近端补贴500pips

处理：
- term=3M 明确给出，方向=结汇(settle)，target_prem_pips=500
- 结构性掉期中 K=FAR，term=3M 时 K 已由曲线唯一确定
- 走报价范式 **1.10 按近端补贴点数反查**的变体——**锁定 term 反查**
  - 扫描范围锁定为 [3M]（只有单点）
  - 调用一次：`--term 3M --settle-purchase settle --currency-pair USDCNY`
  - 取回该 term 下的实际补贴点数
  - 与 target=500 对比
- 若实际补贴点数接近 500 → 返回该方案
- 若实际补贴与 500 偏差较大 → 输出时标注"目标 500 点在 3M 不可达，以下为 3M 的实际方案"

调用计划:
```
调用 1:--term 3M → 取实际补贴点数
输出:3M 方案 + 对比说明
```

### 1.15 补贴点数反查（K=FAR约束）

#### 示例 A7:未给 term，指定了近端补贴点数

**三种等价输入形态（同 A6）：**
1. 结果导向：`"近端结汇价格是6.XXXX"` → 隐含 target_prem_pips
2. 直接补贴：`"近端补贴500pips"` → target_prem_pips=500
3. 对比表达：`"近端比普通即期结汇价格高500pips"` → target_prem_pips=500

用户：
> 结构性掉期结汇方向，美元人民币，近端补贴500pips

处理：
- term 未给，方向=结汇(settle)，币种=USDCNY，target_prem_pips=500
- 结构性掉期中 K=FAR（硬性约束），因此 K 不能自由选择，必须落在某期限的 FAR 上
- 走报价范式 **1.10 按近端补贴点数反查**的变体——**K=FAR 约束扫描**
  - 在 1M~12M 范围内扫描 6 个代表性 term
  - 每个 term 下 K=FAR（由曲线确定），取回对应的补贴点数
  - 找出补贴点数最接近 500 的 2 个方案输出

与 1.5（示例 D1）的关系：实质相同，因为结构性掉期 K=FAR 始终成立。标注为独立示例是为了强调"K=FAR"这一约束在扫描中的底层角色。

调用计划:
```
调用 1:--term 1M → 取补贴值
调用 2:--term 2M → 取补贴值
调用 3:--term 3M → 取补贴值
调用 4:--term 6M → 取补贴值
调用 5:--term 9M → 取补贴值
调用 6:--term 12M → 取补贴值
汇总:筛选出补贴最接近 500 的 2 个 term
```

### 1.16 K 确定求 prem（范式 1.3）

此范式适用于用户同时给出 term 和 K，要求计算该 K 下的期权费补贴。

#### 示例 N1：同时给 term 和 K
用户：
> 3M 结汇结构性掉期，K 定在 7.05

处理：
- term=3M 明确，direction=settle，desired_strike=7.05
- 走报价范式 **1.3 K 确定求 prem**：传入 term=3M, K=7.05 调用脚本
- 脚本返回该 K 下的 prem/pips 及掉期细节，直接透传

调用：
```bash
python bank-derivative-quoting/scripts/opt_structured_swap_query.py --user-id {userId} --currency-pair USDCNY --settle-purchase settle --term 3M --desired-strike 7.05
```

#### 示例 N2：给交割日和 K
用户：
> 2026-09-01 交割的结构性掉期结汇，K 做到 7.10

处理：
- delivery_date=2026-09-01 提供了远端交割日，direction=settle，desired_strike=7.10
- 走报价范式 **1.3 K 确定求 prem** 的变体：delivery_date 替代 term 作为期限锚
- 传入 delivery_date 和 K 调用脚本

调用：
```bash
python bank-derivative-quoting/scripts/opt_structured_swap_query.py --user-id {userId} --currency-pair USDCNY --settle-purchase settle --delivery-date 2026-09-01 --desired-strike 7.10
```

### 1.17 Prem 反求 K（范式 1.4）

此范式适用于用户给出 term 和目标补贴点数，反解达到该补贴所需的 K。

#### 示例 O1：给 term + 补贴点数
用户：
> 3M 结汇结构性掉期，希望近端补贴 200 点

处理：
- term=3M 明确，direction=settle，target_prem_pips=200
- 走报价范式 **1.4 Prem 反求 K**：传入 term=3M, prem=200 调用脚本
- 脚本返回达到 200 点补贴所需的 K 及掉期细节，直接透传

调用：
```bash
python bank-derivative-quoting/scripts/opt_structured_swap_query.py --user-id {userId} --currency-pair USDCNY --settle-purchase settle --term 3M --prem-pips 200
```

#### 示例 O2：补贴点数不可达
用户：
> 3M 结汇结构性掉期，希望近端补贴 1000 点

处理：
- term=3M 明确，target_prem_pips=1000
- 走报价范式 **1.4 Prem 反求 K** 调用脚本
- 若脚本返回结果中实际补贴明显低于 1000（如仅 180 点），输出时标注"目标 1000 点在 3M 不可达，以下为 3M 的实际方案"

### 1.18 双目标探索（范式 1.5）

### 1.20 风格化报价（范式 1.8）

此范式适用于用户给出风险偏好而非具体参数，agent 将风格映射为 delta 反解 K。

#### 示例 R1：保守风格
用户：
> 3M 结汇结构性掉期，保守一点

处理：
- term=3M 明确，direction=settle，风格="保守"
- "保守" = 向 OTM 方向移动，步长视上下文而定（本例取 8d 至 delta=0.27）
- 边界校验：delta=0.27 ≥ 边界 0.15（±35d）→ 校验通过
  - 若步长导致超边界 → clamp 至 15d + `chat` 提示"已触达保守边界"
- 走报价范式 **1.8 风格化报价**：传入 term=3M, delta=0.27

调用：
```bash
python bank-derivative-quoting/scripts/opt_structured_swap_query.py --user-id {userId} --currency-pair USDCNY --settle-purchase settle --term 3M --delta 0.27
```

#### 示例 R2：激进风格
用户：
> 6M 购汇结构性掉期，激进一点，补贴多点

处理：
- term=6M 明确，direction=purchase，风格="激进"
- "激进" = 向 ATM 方向移动，步长视上下文而定（本例移 12d 至 delta=0.47）
- 边界校验：delta=0.47 ≥ 边界 0.15（±35d）→ 校验通过；且未超出 ATM(50d)
  - 若超 ATM → clamp 至 50d + `chat` 提示"已触达激进边界"
- 走报价范式 **1.8 风格化报价**：传入 term=6M, delta=0.47

调用：
```bash
python bank-derivative-quoting/scripts/opt_structured_swap_query.py --user-id {userId} --currency-pair USDCNY --settle-purchase purchase --term 6M --delta 0.47
```
