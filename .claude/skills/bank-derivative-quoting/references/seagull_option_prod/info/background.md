# 海鸥期权产品知识说明

## 0. 文档定位
本文件定义海鸥期权报价 agent 的 **产品元知识、核心原则与实施心法**。阅读顺序见同目录 `README.md`。

## 1. 任务与分层

agent 五步:理解经济结果 → 归一化为内部约束 → 判断是否单次可解 → 若否则规划子调用 → 按契约执行并汇总。

- **认知层**:理解产品与用户、选求解器与组合方式(可灵活)
- **契约层**:脚本参数名、固定文案、输出格式等(必须遵守)

## 2. 核心原则

**先目标后参数**:用户常说的是结果,不是参数名。

**先约束后模式**:先整理约束类型,再选求解器;不要先套「场景几」。

**结果语言有效**:「结汇在 6.9」等需翻译成结构/收益约束,不是无效输入。

**调用纪律**:一次调用对应一个明确子任务。允许:横评、方向对比、先基准再反推、风格对比等多子问题组合。禁止:同参重复、微调试错。

判据:说不清「本次子问题是什么、预期得到什么」则不调脚本。

## 3. 产品定义

海鸥期权 = **远期 + 卖出期权**,期权费补贴远期价,使成交价「更优」。

客户多表达「想做到多少」,agent 负责把结果语言译成参数语言。

### 3.1 方向与期权结构(业务约定,不可改)

| 用户表达 | 内部方向 | 期权结构 |
|---|---|---|
| 结汇 | `settle` | Sell Put |
| 购汇 | `purchase` | Sell Call |

### 3.2 典型需求类型

基准报价;单目标(执行价或补贴);结果目标反推补贴;双目标(同期限下 strike 与补贴);区间扫描(脚本一次出梯度);风格化(激进/保守);单次无法覆盖时的**组合求解**(见 `agent_output/quotation_format.md`「3. 组合求解」)。

## 4. 实施心法

> 报价是「自然语言 → 结构约束 → 选对求解器」,不是套模板命中场景。
>
> 单次为默认;组合须每次调用目的独立、可说明。
>
> 样例学推理路径,不背答案。
>
> 认知层可抽象,契约层不可压缩。
