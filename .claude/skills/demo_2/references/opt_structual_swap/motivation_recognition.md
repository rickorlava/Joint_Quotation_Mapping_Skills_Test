# 结构性掉期产品的目标识别

## 0. 文档定位
本文件定义结构性掉期报价 agent 的 **用户目标识别方式**

## 1. 结构性掉期对客户的补贴价值

结构性掉期的期权费补贴到**掉期的近端**,使得：
- 掉期近端实际成交价比标准掉期更优
- 代价是承担期权被行权的风险

用户除了对 K 和 term 参数直接表达，也可以对补贴点数来表达需求

## 2. 用户的表达方式

用户对结构性掉期的表达可以分为专业的直接需求表达和非专业的间接表达。

### 2.1 直接表达
**直接表达**的特点为直接给出符合结构性掉期报价范式的输入模式，也就是 对 K 和 term 的直接需求，例如对 term 的直接要求：
```
我想要做结构性掉期，方向为结汇，给我一个6m的报价
```
或者对 K 的直接要求：
```
USDCNY 结构性掉期，购汇，我想要执行价7.1的报价
```
也有同时指定了 K 和 term 的要求：
```
给我一个报价：产品为 USDCNY 结构性掉期，方向为购汇，到期为3m，执行价为6.9
```

### 2.2 间接表达
**间接表达**的特点是非专业客户的语句中没有直接给出对 K 的要求，而是通过**市场观点**来隐含一个对 K 的位置。

Agent 必须从客户的观点中反推出合理的 K 以及隐含的结汇与购汇方向。由于**市场观点**不是标准的表达，下面会给出几种常见的市场观点表达类型，以及对应的识别方式。

#### 2.2.1 否定式观点
**否定式观点** 即用户认为汇率不太可能到达某点位，例如
- "我觉得人民币不会贬值到 7.20"
- "汇率不太可能跌破 6.80"
- "应该不会破 7.30"

**K的推理路径**：用户认为不太可能到达的点位，正是适合作为 K 的位置，因为客户认为不会发生的事件如果确实没有发生，卖出的期权就不会被行权，客户可以获取近端的补贴的期权费，因此客户愿意承担对应的被行权风险。

**方向的推理路径**：客户的方向由表达本身决定：
- "不会贬值到 X" → `direction = settle`(结汇情境)
- "不会升值到 X" → `direction = purchase`(购汇情境)
- "不会跌破""不会破 X" → 需结合上下文判断方向,不确定时通过 `chat` 追问

#### 2.2.2 区间肯定式观点

**区间肯定式观点** 即用户认为汇率大概率会落在某个区间，例如

- "我觉得汇率大概率在 7.00 到 7.10 之间"
- "应该会在 6.95~7.05 这个范围"
- "未来这段时间应该都在 7.0 附近"

**K的推理路径**：用户认为的汇率区间为"高概率发生区"，但 K 只有一个，因此 K 应当设在用户认为不太可能发生的区间外侧，使得未来汇率的确落在用户所认为的区间时，客户得以获得近端的补贴的期权费，且期权不会被行权。具体落在区间哪边需要由方向决定。
- 结汇方向: K 设在区间**上沿之上**，因为只要汇率不涨破区间之上,期权就不会被行权，符合客户对汇率的**区间观点**。例:区间 7.00-7.10,结汇 → K 取 7.10 或略高于此
- 购汇方向:K 设在区间**下沿之下**。因为只要汇率不跌破区间之下，期权就不会被行权，符合客户对汇率的**区间观点**。例:区间 7.00-7.10,购汇 → K 取 7.00 或略低于此

**方向的推理路径**：由于区间观点并未对方向做出判断，因此需要结合其他的客户上下文进行方向判断，如果客户没有确定方向，则需要通过 `chat` 追问方向

#### 2.2.3 安全边际表达
**安全边际** 表达并非 **市场观点**，而是对 K 给出了 **相对位置** 而非明确的绝对位置。例如：
- "K 离当前现货远一点"
- "我想 K 设保守一点,远离市场价"
- "K 别太冒险"

**K的推理路径**：这类表达没有给出数值和市场观点，无法根据表达得到 K, 因此要通过 `chat` 引导用户给出自己的观点，询问客户是否希望：
- 给出一个具体的 K 值或区间观点
- 如果用户没有给出 K 值或区间观点的意愿，则根据客户的安全边际表达，按照当前市场标准的"保守" / "中性" / "激进"位置自动选取，选取之前要引导客户给出方向的偏好

**方向的推理路径**：这类表达没有给出方向的观点，因此要通过 `chat` 引导客户给出方向性偏好

#### 2.2.4 补贴点数表达

**补贴点数表达** 为用户没有指定 K 和 term，而是对期权费补贴的点数

**K的推理路径**：K 需要按照 `output_format.md` 的 3.2 按补贴点数反查方式得到

**方向的推理路径**：这类表达没有给出方向的观点，因此要通过 `chat` 引导客户给出方向性偏好

### 2.3 混合表达
**混合表达** 即客户既给出了直接参数，又给出了市场观点，比如

> "应该在 7.0 附近,不会破 7.15,我做个 3M 结汇的"

**K的推理路径**：这种表达为混合式，规定一个优先级：**直接参数 > 否定式观点 > 区间观点 > 安全边际**

### 2.4 结果导向表达

**结果导向表达** 为用户没有直接提补贴点数，但给出了所希望达成的经过补贴后近端的价格

**K的推理路径**：这种表达必须要结合当前远期的价格，使用远期价格减和补贴后价格差得到补贴费用，再走补贴点数表达的推理路径

**方向的推理路径**：方向性隐含在了补贴后价格与远期价格相对高低中，若补贴后价格高于远期价格，则客户是想 sell 掉期，那么方向应该为购汇, 反之结汇
