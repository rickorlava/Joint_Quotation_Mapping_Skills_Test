# 结构性掉期产品的报价范式

## 0. 文档定位
本文件定义结构性掉期报价 agent 的 **合法的报价方式**。

每一种报价范式规定了此情形下：
- 如何调用接口
- 如何将接口所得到的报价结果汇总。
- 汇总报价结果的输出格式

硬约束要求：
- 所有 agent 的动机识别最终**必须**落在所枚举的合法报价范式的其中一种。
- 所有的报价结果**必须**通过调用接口得到

## 合法的报价范式

1. **基准单点报价 term**:给一个 K，求对应的 term
2. **基准单点报价 K**:给一个 term，求对应的 K
2. **沿曲线扫描 K**(组合):固定方向,扫一段 term 区间,得到一组 (term, K) 值
3. **沿曲线扫描 term**(组合):固定方向,扫一段 K 区间,得到一组 (K, term) 值
4. **按补贴点数反查**(组合): 给出用户期望的近端补贴点数, agent 在 1M~12M 区间内扫描一组 term,筛选出补贴最接近目标的两个 term 点位返回
5. **方向对比**(组合):结汇 vs 购汇分别报
6. **币种对比**(组合):不同币种对分别报

## 兜底报价范式
由于强制要求**动机识别**必须落在枚举的合法报价范式中，因此规定一个**兜底报价范式**，当 agent 在动机识别中无法将客户动机映射到任何一种合法报价范式时，将它映射到兜底报价范式

### 历史格式兼容的标准报价范式

老系统存在六字段位置格式:

```
产品 币种 期限 中收 方向 产品报价
```

**历史六字段格式** 也被视作合法，仅作兼容识别,不作为推荐形态

例如:
```
结构性掉期 USDCNY 3M 100pips 结汇 产品报价
结构性掉期 EURCNY 6M 50 购汇 产品报价
```

## 互斥原则

K 和 term 不能同时指定，如果指定了 K 和 term，则必须通过 `chat` 让用户二选一。
这里的同时指定分为两种：
- 同时明确给出了输入参数 K 和 term，例如 "3m结构性掉期购汇报价，我想做到7.2"，客户同时明确指定了 term 和 K
- 客户没有关于 term 和 K 的结构性掉期修饰，但客户表达了**市场观点**，且从市场观点中同时推出了客户对 term 和 K 都有要求，例如 "我想做一个购汇的结构性掉期，我觉得未来6个月人民币不会破7", 这里的 6m 和 7 都是市场观点所隐含，关于**市场观点**，参考**用户目标识别方式**中的**间接表达**章节
- 若客户同时给了市场观点和明确的结构性掉期参数，处理方式参考**用户目标识别方式**中的**混合表达**章节
